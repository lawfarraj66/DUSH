# نظام إدارة مكتب المحاماة (SaaS) — دليل المشروع

## محتويات الحزمة
| الملف | الوظيفة |
|---|---|
| `index.html` | التطبيق كاملاً (ملف واحد). مفاتيح مشروعك الحالي (`xoislbaudcilopdkdebg`) موضوعة في `CFG` |
| `sql/01_supabase_schema.sql` | الجداول + RLS + الصلاحيات + التخزين (الأساس) |
| `sql/02_contracts_patch.sql` | حارس العقود (التعميد والقفل) + عدّاد أرقام العقود |
| `sql/03_accounting_studio_patch.sql` | وحدات البنوك + قفل الفترة المحاسبية |
| `supabase/functions/moyasar-verify` | التحقق من الدفع وتفعيل الاشتراك (عند تفعيل Moyasar) |
| `supabase/functions/send-reminders` | تذكير بريدي تلقائي بالجلسات (اختياري) |


## النشر بالترتيب
1. **قاعدة البيانات:** Supabase ← SQL Editor ← نفّذ الملفات الثلاثة في `sql/` بترتيب أرقامها، كلاً في استعلام مستقل.
2. **البريد:** Authentication ← Providers ← Email ← فعّل **Confirm email**.
3. **الاستضافة:** Cloudflare ← Workers & Pages ← Create ← Pages ← Upload assets ← ارفع `index.html`.
4. **الربط:** ضع رابط الموقع في Supabase ← Authentication ← URL Configuration (**Site URL** و **Redirect URLs**).
5. **أول دخول:** أنشئ حساب مدير المكتب وفعّل بريدك. من «إعدادات المكتب» أدخل اسم المكتب والرقم الضريبي (15 رقماً).

## الدفع (Moyasar) — اختياري
```
supabase login && supabase link --project-ref xoislbaudcilopdkdebg
supabase secrets set MOYASAR_SECRET_KEY=sk_test_xxx
supabase functions deploy moyasar-verify
```
ثم ضع `pk_test_…` في `MOYASAR_PK` داخل `index.html`. **المفتاح السري لا يوضع في الملف أبداً.** عدّل أسعار الخطط في جدول `plans`.

## التذكير بالبريد — اختياري
```
supabase secrets set RESEND_API_KEY=re_xxx REMINDER_FROM="مكتبكم <no-reply@domain.com>" CRON_SECRET=نص_سري
supabase functions deploy send-reminders --no-verify-jwt
```

## قائمة اختبار قبل الاستخدام بيانات حقيقية
- [ ] تسجيل مدير ثم إضافة موكل وقضية، وإعادة تحميل الصفحة: البيانات باقية.
- [ ] الدخول من جوال بالحساب نفسه: نفس البيانات.
- [ ] دعوة سكرتير ومحاسب: كل منهما يرى ما تسمح به صلاحيته فقط.
- [ ] عقد: إنشاء ← تعميد (مدير) ← توقيع. ومحاولة محامٍ مساعد تعميد عقد أو تعديل عقد معمّد: تُرفض.
- [ ] فاتورة بـ QR (بعد إدخال الرقم الضريبي)، وإشعار دائن.
- [ ] تصدير Excel وWord وPDF والطباعة.
- [ ] استيراد كشف بنكي ومطابقة، وقفل فترة وتجربة تعديل فاتورة قديمة.

## ما يحتويه النظام
- **التطبيقات:** شاشة رئيسية بنمط Odoo، والصلاحيات تحدد ما يظهر لكل دور (مدير، محامٍ رئيسي، مساعد، سكرتير، محاسب).
- **القضايا:** قضايا، جلسات، أحكام، مذكرات، تنفيذ، وكالات، تقويم، إشعارات.
- **العقود:** 8 أنواع، أتعاب (مقطوع، نسبة، بالساعة، مختلط، اشتراك)، دفعات، بنود، تعميد بحسب الصلاحية، توقيع بالقلم أو إلكتروني، رقم مميز، بصمة SHA-256، وقفل بعد التعميد.
- **المشاريع:** كانبان وقائمة وغانت، مهام فرعية وتبعيات وتكرار، مؤشرات تقدم، سجل نشاط، ميزانية وربحية.
- **المحاسبة:** فواتير ZATCA (QR) وإشعارات دائنة، ذمم مدينة ودائنة، دفعات جزئية، إقرار ضريبي، بنوك وتسوية، موازنة وتدفق نقدي، قيود، أصول، أمانات، قفل الفترة.
- **الاستوديو:** تعديل الحقول والقوائم والنماذج وقوالب الطباعة (شعار، لون، شروط) لكل البرنامج.

## حدود يجب معرفتها
- **ZATCA:** المرحلة الأولى فقط (QR). الربط والتوقيع والإبلاغ (المرحلة الثانية) غير مضمّنة.
- **الإقرار الضريبي:** ملخص للمراجعة وليس بديلاً عن الإقرار الرسمي.
- **واتساب:** فتح رسالة جاهزة بنقرة. الإرسال التلقائي يحتاج WhatsApp Business API.
- **الاختبار:** اختُبر محلياً في متصفح حقيقي. **لم يُجرَّب** على مشروع Supabase وMoyasar حقيقيين.
- **قفل الفترة والحارس:** يُفرضان بالكامل من الخادم بعد تنفيذ ملفات SQL.
- **تطبيق المستندات** (مجلدات، وسوم، سلة محذوفات) غير منفّذ بعد.
- **منطقة المشروع** `ap-southeast-2` (سيدني) بعيدة عن السعودية.
- **المفتاح السري** (`sb_secret_…`) لا يُشارك ولا يوضع في الملف.
